# LLM Assembly Game (飞机组装游戏)

## Overview

一款面向零基础孩子的桌面飞机组装游戏。用户通过拖拽组件拼装不同
时代的飞机（俯视线稿），每个组件背后映射真实的 LLM 构件。组装完成
后生成配置文件，驱动真实的模型训练，用户可与训练出的模型对话并
完成任务挑战来解锁新时代的飞机和组件。

**Target user**: 零基础孩子 / 初中生（无编程或 AI 知识）
**Discovery**: [discovery-llm-assembly-game.md](discovery-llm-assembly-game.md)
**Constitution**: [constitution.md](constitution.md) v1.1.0

## Functional Requirements

### Requirement 1: Component Drag-and-Drop Assembly
**ID**: REQ-001
**Priority**: High

Users can drag aircraft components from a component panel and drop them
onto designated slots on an aircraft frame. Each slot accepts only
compatible component types. Visual feedback (highlight, snap animation)
indicates valid/invalid placements. Users can remove or replace placed
components at any time before confirming assembly.

**Acceptance criteria**:
- Components can be dragged from panel to aircraft frame slots
- Invalid placements are rejected with visual feedback
- Placed components can be removed or swapped
- Assembly state persists within a session (no accidental loss)

### Requirement 2: Aircraft Era Progression System
**ID**: REQ-002
**Priority**: High

The game presents 5 aircraft eras in chronological order (WWI biplane →
WWII monoplane → 1950s jet → modern fighter → stealth fighter). Each
era introduces new component types that map to increasingly complex LLM
architectures. Users unlock the next era by completing challenge tasks
in the current era. The starting era (WWI biplane) is available
immediately without prerequisites.

**Acceptance criteria**:
- 5 distinct eras are presented in chronological order
- Each era introduces new components not available in prior eras
- Next era unlocks only after completing current era's challenges
- Starting era is available immediately
- Progress is saved between sessions

### Requirement 3: Component-to-LLM Mapping with Dual Labels
**ID**: REQ-003
**Priority**: High

Every game component displays two labels: a game-themed name (e.g.,
"引擎", "机翼") and the real technical name (e.g., "Self-Attention",
"Embedding"). Each component has visible "ability stats" (bars or
numbers) that reflect the corresponding algorithm's actual properties
(e.g., context window size, parameter count, expressiveness).

**Acceptance criteria**:
- Every component shows both game name and technical name
- Ability stats are visible and reflect real algorithm properties
- Stats update dynamically when component configuration changes
- Stat descriptions use plain Chinese accessible to children

### Requirement 4: Config Export from Assembly
**ID**: REQ-004
**Priority**: High

When the user confirms their assembly, the game generates a JSON
configuration file that fully describes the assembled model architecture.
The config format matches the existing myllm `MODEL_CONFIGS` structure
(embedding type, block names, n_embd, n_head, n_layer, dropout, etc.).
Invalid or incomplete assemblies are blocked with a clear explanation
of what is missing.

**Acceptance criteria**:
- Confirmed assembly produces a valid JSON config file
- Config schema matches myllm MODEL_CONFIGS structure
- Incomplete assemblies cannot be confirmed (clear error message)
- Generated config can be read by myllm train.py without modification

### Requirement 5: Model Training with Progress Feedback
**ID**: REQ-005
**Priority**: High

After assembly confirmation, the game launches model training using the
generated config. A progress display shows training status in
game-friendly terms (e.g., "你的飞机正在试飞..." with a progress bar
showing epoch/loss as "飞行稳定性"). Training completes within 60
seconds on CPU for all default configurations. Users can cancel training
at any time.

**Acceptance criteria**:
- Training launches automatically after assembly confirmation
- Progress display updates in real-time with game-friendly language
- All default configs complete training in <60 seconds on CPU
- User can cancel training and return to assembly
- Training errors display a child-friendly error message

### Requirement 6: Chat with Trained Model
**ID**: REQ-006
**Priority**: High

After training completes, the user can type messages and receive
responses generated by their trained model. The chat interface is
presented in-game (e.g., "和你的飞机对话"). Generated text quality
expectations are managed — the UI frames output as the "飞机学会说的
话" with context that simpler aircraft produce simpler output.

**Acceptance criteria**:
- Chat interface available after training completion
- User types input, model generates response
- Response appears within 5 seconds
- UI frames output quality in context of model complexity
- Chat history is visible within the session

### Requirement 7: Task Challenge System
**ID**: REQ-007
**Priority**: High

Each era has a set of challenges that test the assembled model's
capabilities. Challenges are presented as missions (e.g., "让你的飞机
学会说出人名", "让你的飞机能续写一句完整的话"). Completing all
challenges in an era unlocks the next era. Challenge completion is
evaluated by the system (pattern matching or simple heuristics on
generated output).

**Acceptance criteria**:
- Each era has at least 2 challenges
- Challenges are presented as themed missions with clear goals
- System automatically evaluates challenge completion
- Completing all era challenges unlocks the next era
- Challenge status (passed/not passed) is clearly displayed

### Requirement 8: Theme Skin System (Aircraft Only for v1)
**ID**: REQ-008
**Priority**: Medium

v1 ships with a single theme: aircraft top-down line drawings. The
component panel, aircraft frame, slot positions, and visual style all
follow the aircraft theme. The architecture supports future theme
additions (the game-to-LLM mapping layer is separate from the visual
theme layer), but no other themes are implemented in v1.

**Acceptance criteria**:
- Aircraft theme fully implemented with top-down line drawing style
- All 5 eras have distinct aircraft silhouettes
- Component visuals match the aircraft theme
- Theme and LLM-mapping logic are architecturally separated

### Requirement 9: Session Persistence
**ID**: REQ-009
**Priority**: Medium

User progress (unlocked eras, completed challenges, last assembly
state) persists between game sessions. Data is stored locally on the
user's machine. No account or login is required.

**Acceptance criteria**:
- Progress saves automatically when the game closes
- Progress loads automatically when the game reopens
- No login or account required
- Corrupted save data does not crash the game (graceful reset)

### Requirement 10: Chinese-First UI
**ID**: REQ-010
**Priority**: High

All game UI text, tooltips, challenge descriptions, error messages,
and tutorial content are in Simplified Chinese. Language uses plain,
accessible terms with analogies suitable for children. No English-only
UI elements (technical names shown as bilingual labels per REQ-003).

**Acceptance criteria**:
- All UI text is in Simplified Chinese
- Technical terms include Chinese explanation on first appearance
- Language is tested for accessibility by non-technical readers
- No untranslated English-only UI elements

## User Scenarios

### Scenario 1: First-Time User — Building a Biplane
1. User launches the game and sees the WWI era with a biplane frame
2. Component panel shows available parts with game + technical names
3. User drags "机身骨架" (Token Embedding) onto the fuselage slot
4. User drags "螺旋桨" (Bigram 查表) onto the engine slot
5. Frame highlights green — assembly complete
6. User clicks "试飞!" (confirm), JSON config is generated
7. Training begins with progress bar ("飞机正在学习飞行...")
8. Training completes in ~15 seconds
9. Chat interface opens — user types "你好", model generates a response
10. Challenge appears: "让你的飞机说出一个三国人物的名字"
11. User adjusts assembly or retries until challenge passes
12. WWI era complete — WWII era unlocks with new components

### Scenario 2: Returning User — Progressing to Jet Era
1. User reopens game, progress is restored (WWII era unlocked)
2. User selects the 1950s jet era
3. New components available: "多管引擎" (Multi-Head Attention),
   "加力燃烧室" (FeedForward)
4. User assembles a more complex aircraft
5. Training takes ~40 seconds (more parameters)
6. Model generates noticeably better text than biplane
7. Challenges are harder: "让你的飞机续写一段完整的对话"

## Success Criteria

1. A child with zero technical background can complete the first era
   (biplane) without adult help within 15 minutes of first launch
2. 80% of test users can correctly identify which game component maps
   to which LLM concept after completing 2 eras
3. All default model configurations complete training in under 60
   seconds on a standard consumer CPU (Intel i5 or equivalent)
4. Users who complete all 5 eras can explain the basic structure of a
   transformer model in their own words
5. Game file size (excluding Python backend) is under 100MB

## Key Entities

| Entity | Description |
|--------|-------------|
| Component | A draggable game piece mapping to an LLM building block |
| Aircraft Frame | A template with slots that accepts components |
| Era | A chronological stage with its own aircraft, components, and challenges |
| Challenge | A mission that tests the trained model's capabilities |
| Config | JSON file generated from assembly, consumed by myllm |
| Session | Local save data tracking progress and state |

## Assumptions

1. Users have a Windows PC with Python + PyTorch pre-installed (v1);
   bundled installer is a future enhancement
2. Training data (三国演义) is bundled with the game or downloaded on
   first launch
3. CPU-only training is sufficient; GPU support is not required for v1
4. Character-level tokenization is used for all eras; BPE is introduced
   only in the stealth era as an advanced component
5. The existing myllm factory pattern (build_op, build_blocks,
   build_embedding) covers all component types needed for 5 eras
6. Network connectivity is NOT required after initial setup

## Scope Boundaries

**In scope (v1)**:
- Single player, local desktop application
- Aircraft theme with top-down line drawings
- 5 eras with progressive complexity
- Drag-and-drop assembly UI
- JSON config export → Python training → chat
- Task challenge system for era progression
- Local session persistence

**Out of scope (v1)**:
- Additional theme skins (mecha, pet, spaceship)
- Multiplayer or online features
- Mobile platform support
- GPU training support
- Custom training data upload
- Leaderboards or social sharing
- Voice interaction with trained model
- Tutorial or guided walkthrough (beyond UI tooltips)

## Dependencies

- myllm Python codebase (existing: model.py, train.py, generate.py)
- myllm factory pattern (build_op, build_blocks, build_embedding)
- Training data: 三国演义 text file
- Godot 4.4 game engine
- Python + PyTorch runtime on user's machine (v1)

## Open Questions

1. **Component-to-aircraft-part mapping**: Exact naming for each LLM
   component as an aircraft part (e.g., Embedding = 机身骨架? Attention
   = 引擎? FFN = 加力燃烧室?). Needs domain expert + child testing.
2. **Challenge evaluation heuristics**: How to automatically judge if
   generated text "contains a person's name" or "forms a complete
   sentence". Simple regex/keyword matching vs. more sophisticated
   evaluation.
3. **Quality expectation framing**: How to present character-level model
   output (often gibberish for simple models) as a positive learning
   experience rather than a disappointment.
